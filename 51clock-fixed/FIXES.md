# 修复说明（51clock-fixed）

本目录是原工程的副本，仅做缺陷修复，未改动功能与交互设计。
下面按严重程度列出改动点，行号对应本目录中的文件。

---

## 1. 数组越界写：`clock[5]` —— 致命

**文件**：`main.c`
**原状**：`unsigned char clock[5];`（合法下标 0~4），但全程使用 `clock[5]`（秒），
且 `TimeSetSelect %= 6` 允许选中到下标 5 —— 每次读写秒都会写到数组外，
在 Keil 的 data 段布局下极可能正好踩到紧随其后的 `char Alarm`。
结果是 `clock[5] = DS1302_Time[5]` 会把 `Alarm` 赋成秒值：**秒为 0 时闹钟被静默关掉**。

**改动**：改为 `signed char AlarmTime[6];`，并把数组重命名为 `AlarmTime`
（顺带解除与标准库函数 `clock()` 的重名隐患）。

---

## 2. `char` 无符号导致下溢保护全部失效 —— 严重

**文件**：`main.c`、`DS1302.c`、`DS1302.h`
**原状**：Keil C51 中 `char` **默认为无符号**，因此以下判断永远不成立：

- `main.c` `TimeSet()` 中 `DS1302_Time[0] < 0` / `[1] < 1` / `[3] < 0` / `[4] < 0` / `[5] < 0`
- `main.c` `AlarmSet()` 中对应的 `AlarmTime[...] < 0`

后果：在 0 处按"减"会回绕成 255（年显示成 "55"），而不是回到底值。

**改动**：`DS1302_Time[]` 与闹钟数组均显式声明为 `signed char`，
原有的下溢判断因此**按作者本意生效**，逻辑不变、只修语义。

---

## 3. 上电无条件覆盖 RTC —— 严重

**文件**：`main.c`、`DS1302.c`、`DS1302.h`
**原状**：`main()` 初始化时无条件 `DS1302_SetTime()`，
每次上电/复位都把时钟重置为 `2025-01-01 00:00:00`，
DS1302 的掉电保持走时形同虚设。

**改动**：
- `DS1302.c` 新增 `DS1302_IsRunning()`：秒寄存器 CH 位为 0（振荡器在走）且读出的
  月/日合法，才认为 RTC 已有可用时间；
- `main()` 改为：`DS1302_IsRunning()` 为真则 `DS1302_ReadTime()` 直接沿用，
  否则才 `DS1302_SetTime()` 写入初值。

> 注意：首次烧录到一块全新/无电池的板子时，仍会写入一次初值，这是预期行为。

---

## 4. 秒表"突然暂停"（原开发日志中的遗留 bug）

**文件**：`main.c`
**原状**：
- `StopCount` 是 `unsigned char`，中断每 10ms 加一；主循环一旦停顿超过
  约 2.55s（例如长按按键时 `Key()` 里的 `while(P3_x == 0)` 阻塞），计数器回绕 → **这段时间永久丢失**；
- `NowTime.StopSecond_2 += StopCount;` 会把最多 255 直接压进一个 `unsigned char` 位；
- `StopCount` / `TimeSetFlashFlag` 与中断共享却未加 `volatile`；
- 进位靠多层 `if` 嵌套 `while`，可读性差且难以验证。

**改动**：
- `StopCount` 改为 `volatile unsigned int`（可容纳约 10 分钟停顿而不丢时）；
- 读取+清零在 `EA = 0` 临界区内完成，避免 16 位变量被中断撕裂；
- 进位改写为逐位取模/除法的显式进位，不再有截断与嵌套；
- `TimeSetFlashFlag` 加 `volatile`；
- 开始计时（Key 2）时显式清零 `StopCount`，保证从 0 起算。

---

## 5. 闹钟判断取到旧时间

**文件**：`main.c`
**原状**：`Cheak()` 内 `DS1302_ReadTime()` 被注释掉，而它在 `TimeShow()` **之前**调用，
实际比较的是上一轮循环的秒值，报警晚一拍。

**改动**：恢复 `Cheak()` 内的 `DS1302_ReadTime()`。

---

## 6. 蜂鸣器 / LCD_RW 引脚冲突（软件侧已注解，硬件侧需确认）

**文件**：`main.c`、`LCD1602.c`
`main.c` 的 `sbit FMQ = P2^5` 与 `LCD1602.c` 的 `sbit LCD_RW = P2^5` 是**同一根引脚**。
当前之所以能用：LCD 只写不读（RW 恒为 0），蜂鸣期间主循环不访问 LCD，
且 `FMQBeep()` 结束时 `FMQ = 0` 等价于把 RW 复位。

**改动**：在两处都加上显式注释，说明该冲突及"蜂鸣时禁止访问 LCD"的约束。
**真正的修复需要改硬件**（把蜂鸣器换到空闲引脚）；如果在你的板子上蜂鸣器其实
接在别的引脚，只需改 `main.c` 中 `sbit FMQ = P2^5;` 一行。

## 8. 消除重复的合法性校验（可维护性）

**文件**：`main.c`
**原状**：日/月/闰年规则在 `TimeSet()` 增量、`TimeSet()` 减量、`AlarmSet()` 增量、
`AlarmSet()` 减量四处以近乎逐字复制的方式各写一遍；闹钟的"不得早于当前时间"
6 段递进比较又重复了两遍。共约 150 行，改一条规则要同步改四处。

**改动**：抽出三个函数（定义在文件末尾"函数定义部分"）：

- `DaysInMonth(Year, Month)` —— 当月最大天数（含 `%4` 闰年）；
- `Time_Clamp(signed char *t)` —— 把 年 月 日 时 分 秒 统一钳回合法范围，
  同时处理上溢（分 60→0）和下溢（分 -1→59）；
- `Alarm_ClampToNow(signed char *t)` —— 从年向秒逐位比较，把闹钟抬到不早于当前时间，
  与原 6 段递进 `if` 完全等价。

调用点变成：

```c
if(KeyNum == 3) { DS1302_Time[TimeSetSelect]++; Time_Clamp(DS1302_Time); }
if(KeyNum == 4) { DS1302_Time[TimeSetSelect]--; Time_Clamp(DS1302_Time); }
```

`main.c` 从 636 行降到 553 行，且校验规则只剩一处。**行为与原实现一致**
（已逐条比对：闰年 2 月、大小月、上/下溢回绕、闹钟边界钳位的取值都相同）。

顺带修复：`AlarmSet()` 开头补上 `DS1302_ReadTime()`。原来 MODE 2 不走 `TimeShow()`，
`DS1302_Time` 一直是进入本模式前的旧值，导致"闹钟不早于现在"是拿旧时间在比较 ——
若在 MODE 1 里停留了几分钟，可能设出一个当天永远不会触发的闹钟。

## 9. `LCD_ShowNum` 去掉反复计算 10 的幂

**文件**：`LCD1602.c`
**原状**：每位数字都调用一次 `LCD_Pow(10, i-1)`（循环乘），再做一次除法。
**改动**：改为先把各位取到 `unsigned char Buf[5]`，再按显示顺序写出；
删除已无用的 `LCD_Pow`。位数超过 5（unsigned int 上限）时钳到 5。

> 说明：这不是性能优化 —— LCD 写入里的 `LCD_Delay()` 才是耗时大头，
> 这点算术省下的时间可忽略。改它的主要理由是去掉一个多余的辅助函数、让逻辑更直白。

---

## 10. DS1302 读取的健壮性

**文件**：`DS1302.c`
- 读阶段前补 `DS1302_IO = 1;`：8051 准双向口读引脚前必须先把锁存器置 1，
  否则内部下拉管仍导通，会与 DS1302 的输出对拉。原代码只是"碰巧"正确
  （命令字节最高位恰好是 1）。这是时序隐患，不是已复现的故障。
- 读小时寄存器时 `& 0x7F`：屏蔽 bit7（12/24 小时制选择位）。
  若芯片曾被配置成 12 小时制，原代码会把 `0x92` 解析成 92 而非 12。

---

## 11. 定时器初值改为具名常量

**文件**：`Time.h` / `Time.c` / `main.c`
初值 `0xFC67` 直接散落在 8 处。改为 `TIMER_1MS_H` / `TIMER_1MS_L`，
并在 `Time.h` 注明该值对应 **11.0592MHz** 晶振（921 个机器周期 ≈ 1ms）；
12MHz 板子应为 `0xFC18`。数值未变，定时行为不变。

## 12. 闹钟响铃改为非阻塞

**文件**：`main.c`
**原状**：`FMQBeep(1500)` 内部 `Delay(1500)` 死等 1.5 秒，
这段时间主循环完全停摆 —— 按键无响应、时间不刷新。

**改动**：拆成 `FMQBeepStart()` / `FMQBeepStop()`，发声仍由 Timer1 中断翻转
P2^5 产生，但**时长改为中断计数**：

- 新增 `volatile unsigned int BellRemain`（剩余毫秒）与 `unsigned char BellFlag`；
- `Timer2_ISR` 里每 1ms 递减 `BellRemain`；
- 主循环开头新增响铃处理分支：到点、或**按任意键**即 `FMQBeepStop()` 并恢复
  "SHOW" 标签；响铃期间照常调用 `TimeShow()`，走时和按键都正常；
- 响铃时长提为 `#define ALARM_BEEP_MS 1500`，改时长只改这一处。

**行为变化（预期内）**：

- 响铃期间按键可用，任意键可提前停止（原来按键被忽略）；
- 响铃期间显示的是**实时走时**而不是冻结的闹钟时刻
  （原代码显示的是闹钟时刻，但那是个静态画面）；
- 赋 `BellRemain` 时用 `EA = 0` 保护 16 位赋值，避免被中断撕裂。
